# Molish 0.4 语言规范草案

2026-11-25 · 跨尺度定义、证据与应用接口

Molish 以 0.3 的带类型有限机制模型为执行核心。0.4 给它增加版本锁定的生物定义、按需展开、可核查的跨层轨迹投影和应用封包。L2–L4 仍是近期验证重点，L1 的身份和计数继续服务生化原理，L5 可作为包含局部过程的环境。L0 到 L6 的编号用于标注观察和建模尺度。原子机制和组织动力学可以通过各自的模型配置扩展。

## 1. 机器封包

采用 [RFC 8949 §4.2.1](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2.1) 确定性 CBOR 子集。外层是 `["Molish",0,4,kind,body]`。整数范围为 `0…2³²−1`，ID 为正，编号与状态码可为 0。只允许最短无符号整数、有效 UTF-8、定长数组和字节串。摘要均为精确整包 SHA-256 原始 32 字节。JSON 对照将字节串写作小写十六进制。数组的语义顺序保留，其余集合按记录递归字典序排序，拒绝重复、非法版本及尾随数据。

| 种类 | 载荷 |
|---|---|
| 0 模型包 | `[core03, roots, expansions, sources, claims]` |
| 1 查询包 | `[modelDigest, query03]` |
| 2 结果包 | `[modelDigest, queryDigest, result03]` |
| 3 生物定义 | `[namespace, key, version, level, ports, parts]` |
| 4 3D 重放清单 | `[modelDigest, queryDigest, resultDigest, caseId, assets, schedule]` |
| 5 知识图谱快照 | `[modelDigest, queryDigest, resultDigest, caseId, step, staticFacts, state, claimIds]` |
| 6 粗细层轨迹投影 | `[fineBinding, coarseBinding, stateMap, eventMap]` |
| 7 AI 模型提案 | `[baseModelDigest, sourceId, candidate04]` |
| 8 定量适配申请 | `[modelDigest, adapter, timeUnit, species, events]` |
| 9 适配资格回执 | `[modelDigest, requestDigest, status, reasons]` |

`core03`、`query03`、`result03` 是完整的相应 0.3 封包字节，`candidate04` 是完整的 0.4 模型包字节。嵌入包须按其自身版本严格验证。模型包的摘要覆盖定义锁、展开选择、初始条件、规则及来源。外部 CBOR 定义按其锁绑定，无需把全部定义重复嵌进模型包。查询必须同时绑定外层模型摘要与查询内的核心摘要。结果必须绑定这一对外层及核心输入。

在 0.4 中，0.3 的带类型模型、状态和规则构成 **MolIR**。只有一套执行语义。装配后的模型进入有限状态求解，保留轨迹、闭包证书、候选绑定和预算。

## 2. 定义、实例与按需展开

- **定义锁** `[namespace,key,version,digest]` 指向精确的种类 3 封包。身份三元组与摘要均须匹配。版本是定义发行方提供的字符串。参考装配器只接收调用方提供的定义字节，保持可重复的离线校验。
- **层级** `level` 为 0–6。一个定义可以跨层引用另一个定义。层级是分类元数据，不参与类型继承，也不要求每层都有展开对象。
- **端口** `[portId, kind, signature]` 的种类 0、1、2 分别引用核心实体、槽、计数器。签名分别为 `[entityKind]`、`[mode,domainShape]`、`[unit,mode]`。槽的 `domainShape` 取 0 布尔、1 普通枚举、2 实体引用。端口用 `[portId,coreId]` 绑定，本模型中的完整值域和规则类型始终由核心检查。
- **子部件** `[partId,childLock]`。部件身份与位置分开。某个定义的部件可以位于不同空间区室，具体位置由核心关系声明。
- **根实例** `[coreEntity,definitionLock,bindings]`。同一个锁可被多个根实例引用，每个实例拥有自己的实体 ID 和状态。绑定覆盖该定义的全部端口，各端口唯一。显式使用同一核心端口可表示共享状态。
- **选定展开** `[rootEntity,path,coreEntity,bindings]`。路径是一个非空的部件 ID 序列。它的严格前缀须已选择。装配沿部件锁解析准确的子定义，核对其接口与本地实体类型；同根同路径唯一，根与所选部件实例使用互异的核心实体 ID。

只解析根以及明确选择的部件。语义装配碰到所选路径的循环、锁冲突、缺包、端口错配或实例 ID 冲突时，以定位到根和路径的诊断拒绝。实现应施加独立的输入字节、路径深度和已装配定义上限。超限返回装配中止。未展开的后代可以只有引用。若请求以某个未展开的部件为目标，先返回 `DETAIL_NOT_SELECTED`，再由调用方提交包含该部件和相应核心声明的模型包。这个诊断和已声明实体的状态查询为假是两种不同情况。

一个粗层模型可以只声明聚合酶样式的抽象实体和机制所用的端口。它能执行核心中已定义的规则。选取更细的部件、改变执行条件或导入新的规则时，调用方需显式装配相应的核心。新模型包使用新摘要。3D 几何可按资产清单按需加载，资产及时间表不计入模型摘要。

## 3. 科学来源与 AI 入口

模型包的来源与断言记录分别为：

| 记录 | 载荷 |
|---|---|
| 来源 | `[sourceId,origin,issuer,record,version,locator,contentLock]`。来源码 0 文献、1 数据库、2 AI、3 人工。内容锁 `[0]` 表示只保存定位，`[1,digest]` 表示有明确内容版本可核对 |
| 断言 | `[claimId,sourceId,evidenceId,target,stance]`。立场码 0 支持、1 反对、2 仅提及。目标 `[0,entity]`、`[1,rule]` 或 `[2,rel,tuple]`，分别引用核心实体、规则模板和有类型的关系事实 |

证据 ID 必须解析到核心的假设、观测或文献证据记录。来源类别与核心证据类别独立。在给定初态中，根据核心证据的只读上下文守卫筛选适用断言。不同来源的立场同时保留，组合时可以列出冲突的断言 ID。声明的规则仍按自己的守卫执行，来源列表本身不写入状态。调用方如提交已锁定来源的原始内容，须按锁核对摘要。未提供原始内容时，记录仅支持定位与版本追溯。

AI 可以提交类型化查询，或提交绑定原模型摘要的候选包。提案引用候选包中可核对的 AI 来源。验证进程依次检查原模型绑定、候选编码、定义锁、实例映射、证据适用和执行语义。诊断可用 `[code,path]` 返回。接受一份结构合法的提案会产生候选模型摘要，调用方显式选择它用于下一次查询。旧模型查询与证书始终按原摘要核对。文献抽取、数据库适配和模型生成应用都可以通过这些记录提交输入。

## 4. 跨层轨迹投影

选定部件之后，粗层的同一实体可以对应一段细层状态。0.4 提供**单条已核查轨迹的投影**，用于核查细层轨迹与粗层规则的对应关系。

- `fineBinding=[modelDigest,queryDigest,resultDigest,caseId]`。`coarseBinding=[modelDigest,queryDigest]`。每个引用都绑定准确的封包。案例 ID 是该案例初态的确定性 CBOR 摘要，取自当前结果包。
- `stateMap` 给出粗层每个固定槽和计数器对应的一个细层同型字段，并包括细层相关事实如何映射到粗层可变事实。槽对槽的值域、计数对计数的单位必须匹配，且细层的写入值须落在粗层允许范围内。关系映射为显式的 `[fineFact,coarseFact]` 对，目标和来源各自唯一。投影后的粗层状态还须通过结构校验。
- 机器记录为 `[slotPairs,counterPairs,factPairs]`，前两组用 `[coarseId,fineId]`。每个粗层槽和计数器各有一项映射。对于粗层关系，映射两端都必须是可变关系中的合法类型化元组。被映射事实按细层成员资格确定真假；其余粗层动态事实按映射声明为空。
- `eventMap` 使用 `[fineRule,fineBinding,action]`。动作 `[0]` 表示隐藏细层事件，`[1,coarseRule,coarseBinding]` 表示匹配到指定的粗层事件。细层时间次序保留。每条细层事件都须有对应项。
- 验证先重放细层证书，再检查投影初态是合法粗层初态。隐藏事件须保持整份投影状态一致。映射事件须通过粗层规则和干预，且精确到达细层后态的投影。映射了的粗层事件即使没有状态变化，也要执行守卫和干预检查。终点还须满足粗层查询目标。
- 成功投影只为粗层的该初态提供一条可核查见证。跨初态结论、不可达证明及全局等价各自依赖对应证书。两层证据范围继续随各自模型保留。

## 5. 输出、时间与定量边界

### 3D 与证据可追溯的知识图谱

- Molstage 可消费种类 4 的重放清单。资产项为 `[assetId,ownerEntity,digest,locator]`，是独立的呈现绑定。每个资产 ID 唯一，所属实体必须存在。清单须绑定已经核查的见证病例。聚合结果为 `UNKNOWN` 时，仍可选择其中一条已验证、标注初态范围的见证。闭包证书用来说明不可达。重放清单只接受事件见证。
- 时间表 `schedule` 是 `[0]`，或 `[1,[[step,millisecond],…]]`。第 0 步是初态。步号唯一、顺序递增且在见证允许的范围内，时刻非递减。相同时刻按逻辑步号解释。视觉时间可重排长度、暂停和插值。逻辑步、视觉时间和物理时间独立。缺少可选视觉资产时，可用替代视觉显示同一机制状态。
- 种类 5 快照绑定模型、查询、结果、病例及步号。其静态事实与当前完整状态分别输出。状态为 0.3 的 `[slotValues,facts,counterValues]`，来自重放至该步后的结果。适用断言 ID 来自同一模型及初态上下文。输出端把断言当作带来源的陈述，把模型状态事实当作指定推演中的事实。

### SBML / BNGL

定量适配是可选配置。0.4 的资格检查仅判定申请信息是否齐备。有限状态的步数和教学播放秒数均无法提供所需的物理速率。

- `adapter` 为 0（SBML）或 1（BNGL）。物种记录为 `[speciesId,entity,compartment,amountUnit,initialAmount]`，物种 ID 唯一。初始量 `[0]` 为缺省，`[1,n,d]` 为非负约分有理数，分母为正。
- 事件记录为 `[rule,binding,stoichiometry,law,guardMode]`。计量项 `[speciesId,direction,coefficient]` 中 0 消耗、1 产生，系数为正。规则、实例绑定和物种必须存在。动力学声明 `[0]` 为缺省，`[1,amountUnit,timeUnit,digest]` 引用物理规律。0.4 的此配置要求事件里的物种数量单位一致。所写时间、数量单位分别与申请时间单位、对应物种单位匹配。守卫模式 0 表示已给出适配策略，1 表示目前未提供可保持含义的策略。
- 回执状态 0 为 `BLOCKED`，1 为 `READY_FOR_MAPPING`。原因码 0–3 为 `MISSING_RATE`、`MISSING_INITIAL_QUANTITY`、`UNIT_MISMATCH`、`UNSUPPORTED_GUARD`。回执绑定申请摘要。通过资格检查后，适配器仍需要校验物理规律内容及守卫、状态与边界的保真映射。

SBML 的反应可省略动力学，但许多分析和模拟需要它。BNGL 的参数、分子类型、初始物种与反应规则可以作为后续映射目标。进阶适配需逐模型定义哪些 Molish 守卫和状态可翻译。[SBML Level 3 Core](https://sbml.org/specifications/sbml-level-3/version-2/core/release-1/sbml-level-3-version-2-core.pdf) · [BioNetGen 教程](https://bionetgen.org/tutorial)

## 6. 验收与迁移

以下有向转运使用合成示例。粗层可直接执行跨区事件。细层在位置变化前有一个局部接触事件。定义、模型、查询和结果分别锁定。细层接触对粗层可隐藏，随后同一跨区变化须投影到粗层的合法事件。

| 验收点 | 预期 |
|---|---|
| 定义复用与按需展开 | 两个实例共享同一 L3 定义，身份和状态各自独立。未选 L2 部件允许省略，选中后须核对正确定义及端口。错误摘要、循环与 ID 冲突均拒绝 |
| 来源与候选模型 | 一条规则的支持与反对可同时记录，证据只在声明的上下文适用。旧模型摘要无法冒用新候选 |
| 轨迹投影 | 细层局部接触可隐藏。隐藏会改变粗层位置的事件、映射绕过粗层守卫或被干预禁止的事件均拒绝 |
| 3D 与图谱 | 可视资产和教学时间变化产生新的呈现清单。机制状态与证书校验结果一致。同一见证的两个快照对应不同步号，可精确追溯 |
| 模拟 | 只有离散计数与条件的模型得到缺少动力学规律的诊断 |

迁移 0.3 时，将原模型字节放入种类 0，定义与证据外层表可为空。包装原查询及结果时各自绑定新外层摘要。旧的 0.3 摘要和证书仍能在其原核心范围内单独核查。

## Molish 0.3 语言规范草案

2026-11-25 · 生物结构与可复用规则

Molish 面向细胞生物学、分子生物学和分子层级的生物化学原理。0.3 在 0.2 的有限状态、干预、证据与重放语义上增加类型化关系、有方向的轨道与区间，以及有界计数。规则以对象角色声明，可在新位点、不同轨道或不同离散条件下实例化。Molstage 消费同一份见证轨迹。

本版的材料粒度由模型定义，例如核酸片段、蛋白复合体、运输站位或计数的分子类。规则描述位置、结合、调控及状态耦合。有机化学的逐原子机制和实时数值动力学可由独立配置扩展。三个验收模型使用合成对象和抽象计数。

### 1. 模型和值

0.3 封套为 `["Molish",0,3,kind,body]`。类别 0 的模型载荷是以下固定元组。

```text
[core, sorts, relations, counters, tracks, ranges, staticFacts, initial, templates]
core = [entities, domains, slots, evidence, modules, coverage, gaps, spatial]
```

`core` 复用附录中的固定槽、结构性模块端口、证据上下文与空间记录。状态包含固定槽向量、可变关系事实集合和计数器向量。实体 ID 在同一模型内稳定。需要表示产物、片段或载体在后续出现时，预先分配可用的有限实体，并通过状态或关系记录何时存在、位于何处。持久材料 ID 不能通过换标签被复用为另一份材料。

| 记录 | 形式与含义 |
|---|---|
| 类型集合 `sorts` | `[sortId,entityIds]`，非空有限实体集合。不同类型集合可以显式重叠 |
| 关系 `relations` | `[relId,argSorts,mode,keys]`，参数类型列表非空。模式 0 静态，模式 1 可变。每个键为非空的参数位置列表，位置从 0 起。相同键投影最多有一个关系元组 |
| 事实 | `[relId,[entityId,…]]`。各参数必须属于对应类型。静态事实只出现在 `staticFacts`。可变事实只出现在状态中 |
| 计数器 `counters` | `[counterId,ownerEntity,unit,max,mode]`，范围 `0…max`。模式 0 可写，模式 1 只读。单位为模型中的精确字符串 |
| 轨道 `tracks` | `[trackEntity,[site,…]]`。非空、有序、无重复。同一站位在一个模型中最多归属于一条轨道 |
| 区间 `ranges` | `[rangeEntity,trackEntity,start,end]`。索引从 0 起且 `0≤start<end≤length(track)`，范围为半开区间 `[start,end)` |
| 状态 | `[slotValues,facts,counterValues]`。两个向量按各自 ID 升序排列，`facts` 是规范排序的可变事实集 |

坐标站位与材料是独立对象。材料状态、结合和连通由关系记录。切开材料或替换片段不会改写轨道的站位序号。当前连接关系可以是可变关系。两条轨道上的配对或对应需要独立声明，索引相同只说明各自的顺序。

#### 初态

- `[0,slotInitial,facts,counterValues]` 复用 0.2 的槽初态编码。每组槽值共享后面的完整事实与计数。
- `[1,[state,…]]` 显式枚举完整状态，支持槽、关系和计数之间的相关性。每个状态单独通过类型与键约束检查，集合非空并按规范顺序去重。

在某个声明状态中，合法事实元组通过成员查询获得真假。模型覆盖和证据适用范围沿用 0.2，成员查询的真假只陈述当前模型。

### 2. 有限规则模板

模板条目为 `[moduleId,ruleId,binders,when,effects,evidence]`。模板规则与核心的固定规则共享同一个全局规则 ID 空间。`binders` 按绑定顺序给出类型集合 ID。固定规则的绑定为空数组。

操作数 `[0,entityId]` 是常量，`[1,index]` 是从 0 起的绑定变量引用。变量取值来自声明类型，随后按使用处的参数类型检查。常量越类型、索引越界和静态关系写入属于装配错误。变量绑定时遇到不兼容的参数会过滤该实例。模板守卫继承所属模块的核心守卫。规则证据为直接引用和模块证据的并集。

| 谓词 | 机器表示 |
|---|---|
| 槽等式或区室包含 | 沿用核心 `[0,slot,value]` 和 `[1,entity,compartment]` |
| 关系成员或非成员 | `[2,rel,terms]` 或 `[3,rel,terms]` |
| 轨道正向相邻 | `[4,trackTerm,fromTerm,toTerm]` |
| 站位在区间内 | `[5,rangeTerm,siteTerm]`，站位须属于区间指定轨道 |
| 区间所在轨道 | `[6,rangeTerm,trackTerm]` |
| 比较有限计数 | `[7,comparison,left,right]`。比较码 0 至 5 为等于、不等于、小于、小于等于、大于、大于等于 |
| 关系键待填 | `[8,rel,keyIndex,terms]`，键索引从 0 起，参数与所选键位匹配，当前状态找不到该键时为真 |
| 两个实体不同 | `[9,leftTerm,rightTerm]` |

计数表达式为 `[unit,constant,[[counter,coefficient],…]]`。常量和系数为无符号整数、系数为正，所有引用计数器的单位必须与表达式一致。比较的两边单位相同。表达式实际按整数精确求值。引用用只读计数器可以让同一模板按上下文变更一个有单位的消耗量。

| 原子写入 | 机器表示 |
|---|---|
| 赋固定槽值 | `[0,slot,value]` |
| 写入／移除关系事实 | `[1,rel,terms]` 或 `[2,rel,terms]`，定义为集合插入与删除 |
| 增加／减少计数 | `[3,counter,direction,expression]`，0 增加，1 减少，表达式单位须等于被更新计数器的单位 |

每步只提交一个实例。它的模板守卫、模块守卫、算术右侧与移动边守卫都读取同一个前态。求值后产生完整候选状态，再检查槽与计数范围、关系键、只读状态、空间关系和查询干预，通过后整步提交。写入目标别名产生相同值时合并。不同值、同一元组的同时增删和同一计数器多个独立增减使该实例无后继，可由诊断报告冲突。扣减不足或超出上限也无后继。用有类型的业务守卫表达预期失败条件，可让诊断定位到规则本身。

结构性约束验证状态是否可表示，例如重复占位违反关系键。机制性质则用于查询，例如代价与产物计数是否耦合。一个结构合法却违反耦合的变体应能产生反例。

### 3. 查询、预算与证书

| 类别 | 载荷 |
|---|---|
| 1 查询 | `[modelDigest,quantifier,target,forbid,limits]` |
| 2 结果 | `[modelDigest,queryDigest,verdict,allInitialsProved,stop,cases]` |

`target=[binders,conditions]`。谓词合取必须非空。在一个状态中，存在至少一组合法目标绑定使合取成立则命中目标。`ANY=0` 问是否至少一个初态可达，`EACH=1` 问是否每个初态都各自有可达路径。状态内部的目标绑定和跨初态的量词按此顺序解释。结果维持 `YES=0`、`NO=1`、`UNKNOWN=2`，开放覆盖在结果之外标记。

| 查询 | YES 所需证书 | NO 所需证书 |
|---|---|---|
| ANY | 任一合法初态的见证 | 所有合法初态的不可达证书 |
| EACH | 所有合法初态的见证 | 任一合法初态的不可达证书 |

干预沿用 `[0,rule]` 禁用所有绑定、`[1,slot,value]` 禁止进入固定槽值、`[2,entity,compartment]` 禁止进入区室，新增 `[3,rule,binding]` 禁用指定规则实例。后者的绑定长度、顺序和值类型必须与模板声明一致。

`limits=[maxInitials,maxStates,maxChecks,maxCaseBytes]` 为全局正整数预算。按字典序延迟枚举初态。参考搜索对每个初态做广度优先搜索，同状态去重，后继按规则 ID 及绑定向量顺序产生。每次开始检查一组候选规则绑定或一组目标绑定都收费 1，包括通过静态守卫或类型可以淘汰的候选。检查目标时首个可用绑定为参考选择。每次纳入新的具体状态才增加状态计数，且不同初态分别计入。初态或后继被接收时立即检查目标，再把尚未命中的状态加入待扩展队列。预算阈值只在下一项必要操作超限时触发。实现可用索引加速，但参考结果的预算口径按上述候选顺序等价计算。

`maxCaseBytes` 对返回案例的确定性 CBOR 字节数计费。可核查的已完成案例可以保留，未完成初态由全局停止原因表示。结果停止码依次为 `COMPLETE`、`DECISIVE`、`INITIAL_LIMIT`、`STATE_LIMIT`、`CHECK_LIMIT`、`CASE_BYTES_LIMIT`。全量完成优先标为 `COMPLETE`，已收集的证书足以得出结论时允许提前返回 `DECISIVE`。初态与状态额度同时不足时先记初态额度。

案例仍为 `[state,kind,proof]`。见证类型 0 的证明为 `[events,targetBinding]`。每个事件为 `[ruleId,binding,delta]`，其中增量只列实际变化，四类记录分别是 `[0,slot,newValue]`、`[1,rel,tuple]`、`[2,rel,tuple]`、`[3,counter,newValue]`。不可达类型 1 的证明是包含初态、在干预下对允许后继封闭、与目标不相交的有限状态集合。

验证器核对模型及查询摘要、合法初态、每一步与绑定的实际增量，并确认终态满足所给目标绑定。闭包则重新计算后继并对目标绑定做有限检查。所附证书须足够支持结论和完整覆盖标志，见证合法性可独立于参考求解器的最短性验证。验证预算耗尽时返回验证未完成。Molstage 以验证通过的事件、对象 ID 和增量为输入，保留自己的呈现时间和插值。

### 4. 机器编码与迁移

权威交换采用 [RFC 8949 §4.2.1](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2.1) 的确定性 CBOR 子集。只使用定长数组、最短无符号整数、有效 UTF-8 文本和定长字节串。所有 ID 为正，布尔值域 0 除外。索引、类型码等可为 0。整数编码值范围是 `0…2³²−1`。中间算术使用精确整数，写回必须遵守已声明的范围。

- ID 表按 ID 升序，模板按全局规则 ID 升序，事实、案例、显式初态、闭包、条件、效果、干预和证书增量按记录递归字典序。对于递归字典序，值类型依次为整数、字节串、文本、数组。整数按数值，字节串和文本按字节，数组按元素且真前缀排前。集合无重复。
- 参数类型、键中的位置及各键参数语义依各自记录定义。键的位置严格递增，键列表按字典序。轨道站位、绑定变量、原子数值向量与事件均保留语义顺序。
- 模型及查询摘要用完整封套的 SHA-256 原始 32 字节。严格解码校验顺序、范围、版本和尾随数据，并有独立的输入字节与深度上限。同语义 JSON 对照用相同元组，字节摘要为 64 位小写十六进制。JSON 对照按同一模型和查询语义计量 token、修复成本及有效结论率。
- 从 0.2 迁移时，从原模型取出槽初态放入 `[0,slotInitial,[],[]]`，余下包进 `core`。新表和模板为空。原查询目标包装为 `[[],conditions]`。重设预算计费并重算摘要。旧轨迹可按 0.2 解码并在新模型上重新产生证书。

| 记录 | 0.3 中沿用的含义 |
|---|---|
| 实体 | `[id,kind,label]`，0 分子实体、1 区室、2 调控对象。0.3 增加 3 结构对象，由类型集合细化其用途 |
| 值域、槽 | `[id,kind,codes]`，种类 0 枚举、1 同种类实体引用。布尔值域 0 内建。`[id,entity,name,domain,mode]`，模式 0 可变、1 只读 |
| 证据与覆盖 | `[id,kind,source,context,applies]`。0 假设、1 观测、2 文献。适用谓词是只读固定槽等式。`coverage=0` 时缺口为空，开放时为 1 并列明缺口 |
